## 🔴 Redis 缓存结构

### **一、计数系统**

#### **1. Bitmap 事实层**

```
Key: bm:{metric}:{entity_type}:{entity_id}:{chunk}
Type: String (Bitmap)
Value: 位图分片（每个分片 32K 位 = 4KB）

示例：
bm:like:knowpost:4194439168:0      ← 知文 4194439168 的点赞 Bitmap（第 0 片）
bm:fav:knowpost:4194439168:0       ← 知文 4194439168 的收藏 Bitmap（第 0 片）

结构：
offset_0 → 用户 ID % 32768 = 0 的用户是否点赞
offset_1 → 用户 ID % 32768 = 1 的用户是否点赞
...
offset_32767 → 用户 ID % 32768 = 32767 的用户是否点赞

TTL: 永久（除非手动删除）
```

---

#### **2. Hash 聚合桶（缓冲层）**

```
Key: agg:{schema_id}:{entity_type}:{entity_id}
Type: Hash
Value: {field: delta}

示例：
agg:v1:knowpost:4194439168
  field "1" → +1    ← 用户 ID=1 的点赞增量
  field "5" → +1    ← 用户 ID=5 的点赞增量
  field "10" → -1   ← 用户 ID=10 取消点赞

TTL: 刷写到 SDS 后删除字段（动态维护）
```

---

#### **3. SDS 计数层（最终计数）**

```
Key: cnt:{schema_id}:{entity_type}:{entity_id}
Type: String (二进制串)
Value: 20 字节的固定结构（5 个 32 位大端序整数）

示例：
cnt:v1:knowpost:4194439168

字节布局（20 字节）：
┌─────────────┬─────────────┬─────────────┬─────────────┬─────────────┐
│   idx1      │   idx2      │   idx3      │   idx4      │   idx5      │
│   like      │   fav       │   read      │   comment   │   share     │
│   4 字节     │   4 字节     │   4 字节     │   4 字节     │   4 字节     │
└─────────────┴─────────────┴─────────────┴─────────────┴─────────────┘

值：0x000F4240 000186A0 001B7740 000003E8 00000064
含义：like=1000000, fav=100000, read=1800000, comment=1000, share=100

TTL: 永久（LRU 淘汰）
```

---

#### **4. 聚合桶 Lua 脚本**

```lua
-- Key: cntKey (SDS Key)
-- ARGV[1]: field 名称（如 "1" 代表用户 ID=1）
-- ARGV[2]: delta（增量）
-- ARGV[3]: schemaId（版本号）
-- ARGV[4]: idx（指标索引，从 1 开始）
-- ARGV[5]: metric（指标名称）

local sds = redis.call('GET', KEYS[1]) or ('\0'):rep(20)
local off = (tonumber(ARGV[4]) - 1) * 4
local n = 0
for i = 0, 3 do 
    n = bit.bor(n, bit.lshift(bit.band(string.byte(sds, off + i + 1), 0xFF), 8 * (3 - i))) 
end
n = n + tonumber(ARGV[2])
for i = 0, 3 do 
    sds = sds:sub(1, off + i) .. string.char(bit.rshift(n, 8 * (3 - i)) & 0xFF) .. sds:sub(off + i + 2) 
end
redis.call('SET', KEYS[1], sds)
redis.call('HDEL', KEYS[2], ARGV[1])  -- 成功后删除 Hash 字段
```

### **二、Feed流系统**

#### **1. Feed 页面缓存（正向索引）**

```
Key: feed:public:{size}:{page}:{version}
Type: String (JSON)
Value: FeedPageResponse 对象的 JSON 序列化

示例：
feed:public:20:1:v1

{
  "items": [
    {
      "id": "4194439168",
      "title": "知文标题",
      "description": "描述",
      "images": ["url1", "url2"],
      "authorId": "123",
      "authorNickname": "作者名",
      "authorAvatar": "avatar_url",
      "likeCount": 100,
      "favCount": 50,
      "isTop": false,
      "publishTime": "2024-03-06T14:30:00Z"
    },
    ... (共 20 条)
  ],
  "page": 1,
  "size": 20,
  "hasMore": true
}

TTL: 7200s (2 小时)
```

---

#### **2. 反向索引（按小时分片）**

```
Key: feed:public:index:{postId}:{hourSlot}
Type: Set
Value: {页面 Key 集合}

示例：
feed:public:index:4194439168:474898

["feed:public:20:1:v1", "feed:public:20:2:v2"]

说明：
- postId: 知文 ID
- hourSlot: 小时槽 = currentTimeMillis / 3600000
- 记录某篇知文出现在哪些 Feed 页面中

TTL: 7200s (2 小时)
```

---

#### **3. Feed流内容片段缓存**

```
Key: feed:item:{postId}
Type: String (JSON)
Value: 单条知文的精简信息

示例：
feed:item:4194439168

{
  "id": "4194439168",
  "title": "标题",
  "likeCount": 100,

  "authorId": "123",

}

```

### **三、关系系统**

#### **1. 关注列表（ZSet）**

```
Key: uf:flws:{userId}
Type: ZSet
Value: {toUserId: timestamp}

示例：
uf:flws:123

成员                    分数（时间戳）
"456"                  1709632800000  ← 关注了用户 456
"789"                  1709636400000  ← 关注了用户 789
"101"                  1709640000000  ← 关注了用户 101

按分数倒序排列（最新关注的在前面）
TTL: 7200s (2 小时)
```

---

#### **2. 粉丝列表（ZSet）**

```
Key: uf:fans:{userId}
Type: ZSet
Value: {fromUserId: timestamp}

示例：
uf:fans:123

成员                    分数（时间戳）
"456"                  1709632800000  ← 用户 456 是粉丝
"789"                  1709636400000  ← 用户 789 是粉丝

TTL: 7200s (2 小时)
```

---

#### **3. 令牌桶限流**

```
Key: rl:follow:{userId}
Type: Hash
Value: {last: timestamp, tokens: count}

示例：
rl:follow:123

{
  "last": "1709632800",      ← 上次更新时间戳（秒）
  "tokens": "95"             ← 当前剩余令牌数
}

容量：100 个令牌
速率：1 个/秒
PEXPIRE: 60000ms (1 分钟)
```

---

#### **4. 幂等去重键**

```
Key: dedup:rel:{type}:{fromUserId}:{toUserId}:{id}
Type: String
Value: "1"

示例：
dedup:rel:FollowCreated:123:456:999

作用：防止重复处理同一个关系事件
TTL: 600s (10 分钟)
```

## 🟡 Caffeine 本地缓存

### **1. 知文详情缓存**

```java
@Bean("knowPostDetailCache")
public Cache<String, KnowPostDetailResponse> knowPostDetailCache() {
    return Caffeine.newBuilder()
        .maximumSize(10000)           // 最多 1 万条
        .expireAfterWrite(Duration.ofHours(2))  // 写入后 2 小时过期
        .recordStats()                // 记录统计信息
        .build();
}

Key: "knowpost:detail:4194439168:v1"
Value: KnowPostDetailResponse 对象（Java 对象，无需序列化）

优势：
✅ 微秒级访问（~0.01ms）
✅ 减少 Redis 压力
✅ 无需序列化/反序列化
```

## 🔵 MySQL 数据库表结构

### **1. knowpost（知文主表）**

```sql
CREATE TABLE `knowpost` (
  `id` BIGINT NOT NULL COMMENT '雪花算法 ID',
  `creator_id` BIGINT NOT NULL COMMENT '作者 ID',
  `status` VARCHAR(20) NOT NULL DEFAULT 'draft' COMMENT '状态：draft/published/deleted',
  `type` VARCHAR(20) NOT NULL DEFAULT 'image_text' COMMENT '类型：image_text/video/audio',
  `visible` VARCHAR(20) NOT NULL DEFAULT 'public' COMMENT '可见性：public/followers/school/private/unlisted',
  `is_top` BOOLEAN NOT NULL DEFAULT FALSE COMMENT '是否置顶',
  
  -- 内容相关
  `content_object_key` VARCHAR(255) DEFAULT NULL COMMENT 'OSS 对象键',
  `content_etag` VARCHAR(100) DEFAULT NULL COMMENT 'OSS ETag',
  `content_size` BIGINT DEFAULT NULL COMMENT '文件大小（字节）',
  `content_sha256` VARCHAR(64) DEFAULT NULL COMMENT 'SHA256 校验和',
  `content_url` VARCHAR(512) DEFAULT NULL COMMENT '公共访问 URL',
  
  -- 元数据
  `title` VARCHAR(200) DEFAULT NULL COMMENT '标题',
  `tag_id` BIGINT DEFAULT NULL COMMENT '标签分类 ID',
  `tags` JSON DEFAULT NULL COMMENT '标签数组',
  `img_urls` JSON DEFAULT NULL COMMENT '图片 URL 数组',
  `description` TEXT DEFAULT NULL COMMENT '描述/摘要',
```

## 📊 索引结构汇总

### **Redis 索引类型**

| 类型 | 用途 | 示例 |
|------|------|------|
| **String** | 缓存、计数器、Bitmap | `knowpost:detail:123`, `cnt:v1:knowpost:123` |
| **Hash** | 聚合桶、限流状态 | `agg:v1:knowpost:123`, `rl:follow:123` |
| **Set** | 反向索引 | `feed:public:index:123:474898` |

## 🎯 设计要点总结

### **1. 多级缓存架构**

```
L1: Caffeine 本地缓存（微秒级）
  ↓
L2: Redis 分布式缓存（毫秒级）
  ↓
L3: MySQL 数据库（兜底回源）
```

---

### **2. 计数系统三层架构**

```
Bitmap 事实层（同步写，抗高并发）
  ↓
Hash 聚合桶（异步合并，削峰填谷）
  ↓
SDS 计数层（定时刷写，快速查询）
```

---

### **3. Feed 流双索引设计**

```
正向索引：页面 → 包含哪些知文（Feed 页面缓存）
  ↓
反向索引：知文 → 出现在哪些页面（快速定位更新）
  ↓
时间窗口：按小时分片，防止无限膨胀
```

---

### **4. Outbox 模式保证最终一致性**

```
业务操作 → 写入 outbox 表（同事务）
  ↓
Canal 监听 binlog
  ↓
Kafka 异步投递
  ↓
消费者更新计数/缓存
```

---

### **5. 热点自动识别**

```
访问记录 → HotKeyDetector 统计
  ↓
热度分级（冷门/普通/热门/超热）
  ↓
动态调整 TTL（60s ~ 3600s+）
  ↓
大 V 专属本地缓存
```
